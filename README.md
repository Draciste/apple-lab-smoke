# Synthetic macOS 27 browser probe

This standalone repository contains only synthetic fixtures. It runs manually via `workflow_dispatch` on GitHub.com standard `xcode-27` (Apple Silicon), with a 30-minute timeout and one concurrency group. The job is gated on the event and context reporting a public repository. It checks Darwin/arm64 at runtime and retrieves exactly the event commit over anonymous HTTPS. Do not add private code, secrets, personal paths or data. Review all changes and visibility before publication or dispatch; a visibility change after job admission is not an atomic billing guarantee.

Sources: [runner labels](https://github.com/actions/runner-images#available-images), [xcode-27 preview](https://github.com/actions/runner-images/issues/14404), [image software](https://github.com/actions/runner-images/blob/main/images/macos/xcode-27-arm64-Readme.md), [billing](https://docs.github.com/en/actions/concepts/billing-and-usage), [larger runner billing](https://docs.github.com/en/billing/concepts/product-billing/github-actions), [Safari automation](https://developer.apple.com/documentation/safari-developer-tools/macos-enabling-webdriver).

The fixture checks English/Czech JSON through a subprocess using Unicode directory and file names. It serves synthetic HTML on loopback and attempts headed sessions with genuine Safari/safaridriver, stock Firefox/geckodriver and Chrome/chromedriver, using the W3C WebDriver protocol directly (no Selenium client dependency). It compares rendered DOM text, and outputs JSON with per-browser status and version to logs and job summary. A failed or unverified Safari, Firefox, Chrome or Opera browser fails the job and is not proof of browser capability. The workflow attempts `safaridriver --enable` without elevation on the ephemeral runner; it may still fail due to permissions. Do not run that enabling step on a personal Mac without intending to change its setting. Safari is Safari, not a WebKit substitute. A separate headless Chrome probe requests only the loopback CDP `/json/version` endpoint. Its status is informational and does not fail the job. Chrome and Firefox attempt a synthetic local HTTP download into separate temporary directories and verify the downloaded bytes. Safari download is unverified. Driver failures include the phase and the last 6000 bytes of the driver log; session creation is bounded at 90 seconds. A bounded Safari MCP stdio probe attempts only initialize and tools/list, with no browser tool calls; an error or timeout is unverified. Desktop interaction and remote desktop are not tested. No browser security or TLS settings are disabled; temporary server, drivers and profile data are stopped with the job. This test does not expose a persistent service.

To run locally on macOS, execute `python3 probe.py`; its output may contain a machine-generated temporary path only in exceptional error messages. The source is designed for public synthetic CI and needs no external Python packages. A Windows syntax or fixture check cannot prove macOS/browser execution.

On a disposable GitHub.com Actions runner only, the Opera probe downloads the pinned Opera 137.0.6036.63 macOS disk image from the [official Opera archive](https://get.geo.opera.com/pub/opera/desktop/137.0.6036.63/mac/), checks the actual response Content-Type and pinned SHA-256, then mounts it read-only, verifies Apple trust and the Opera bundle identifier and Team ID, checks Gatekeeper, copies the app into temporary storage, and attempts a headed-independent CDP render in a fresh headless profile. It checks the synthetic DOM and Opera user-agent; Opera download is unverified. Acquisition, signature or launch failures are reported as unverified and fail the job. The pinned digest matches the adjacent Opera archive checksum and the independently published Homebrew cask digest; the version is intentionally fixed and is not a claim of current latest. The Team ID and bundle identifier are independently listed by [Apple](https://github.com/apple/password-manager-resources/blob/main/quirks/web-browser-extension-distribution-information.json) and the Team ID is published by [Opera](https://blogs.opera.com/security/2018/05/opera-53-on-macos-new-application-signature-why-you-are-getting-asked-to-grant-opera-access-to-your-macs-keychain/). Downloads and probe runtime are bounded. The installer and app are discarded with the runner; no sandbox or TLS protection is disabled. Safari MCP setup is documented by [WebKit](https://webkit.org/blog/18136/introducing-the-safari-mcp-server-for-web-developers/).
