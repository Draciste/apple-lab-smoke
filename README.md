# Synthetic macOS 27 browser probe

This standalone repository contains only synthetic fixtures. It runs manually via `workflow_dispatch` on GitHub.com standard `xcode-27` (Apple Silicon), with a 30-minute timeout and one concurrency group. The job is gated on the event and context reporting a public repository. It checks Darwin/arm64 at runtime and retrieves exactly the event commit over anonymous HTTPS. Do not add private code, secrets, personal paths or data. Review all changes and visibility before publication or dispatch; a visibility change after job admission is not an atomic billing guarantee.

Larger runners are charged even in public repositories. This workflow deliberately uses neither larger runners nor Actions, cache or artifact uploads. Logs and job summaries are retained by GitHub according to its policy; they are public in a public repository. Sources: [runner labels](https://github.com/actions/runner-images#available-images), [xcode-27 preview](https://github.com/actions/runner-images/issues/14404), [image software](https://github.com/actions/runner-images/blob/main/images/macos/xcode-27-arm64-Readme.md), [billing](https://docs.github.com/en/actions/concepts/billing-and-usage), [larger runner billing](https://docs.github.com/en/billing/concepts/product-billing/github-actions), [Safari automation](https://developer.apple.com/documentation/safari-developer-tools/macos-enabling-webdriver).

The fixture checks English/Czech JSON through a subprocess using Unicode directory and file names. It serves synthetic HTML on loopback and attempts headed sessions with genuine Safari/safaridriver, stock Firefox/geckodriver and Chrome/chromedriver, using the W3C WebDriver protocol directly (no Selenium client dependency). It compares rendered DOM text and outputs JSON with per-browser status and version. The workflow attempts `safaridriver --enable` without elevation on the ephemeral runner; it may fail due to permissions. Do not enable it on a personal Mac without intending to change that setting. Chrome and Firefox attempt synthetic downloads into separate temporary directories and verify the bytes. Safari attempts a uniquely named synthetic download only on the disposable GitHub.com runner, checks exact bytes in `~/Downloads` without changing preferences, and removes that exact file. This is an observed location, not a WebDriver destination guarantee; an absent file remains unverified. Driver failures include the phase and log tail.

The bounded Safari MCP probe records tool names and input schemas. On the disposable runner, if the documented `navigate_to_url` tool has a directly usable URL-only required schema, it calls it on the fixture while the loopback server runs and checks the returned text. Incompatible schemas, errors, timeouts or missing text remain unverified. The call may navigate the current Safari tab and is restricted to the disposable runner. Safari download and MCP call statuses are informational for the exit code: a passing job alone does not establish them. No browser security or TLS settings are disabled. Desktop interaction and remote desktop are not tested.

To run locally on macOS, execute `python3 probe.py`; its output may contain a machine-generated temporary path only in exceptional error messages. The source is designed for public synthetic CI and needs no external Python packages. A Windows syntax or fixture check cannot prove macOS/browser execution.

On a disposable GitHub.com Actions runner only, the Opera probe downloads the pinned Opera 137.0.6036.63 macOS disk image from the [official Opera archive](https://get.geo.opera.com/pub/opera/desktop/137.0.6036.63/mac/), checks Content-Type and SHA-256, mounts it read-only, verifies the Opera signature and Apple trust, checks Gatekeeper and copies the app into temporary storage. It checks synthetic DOM and Opera user-agent in a fresh headless profile. Its experimental CDP download probe requires matching start and completion events and exact downloaded bytes. Acquisition, signature, launch or download errors are unverified and fail the job. The installer and app are discarded with the runner. Safari MCP setup is documented by [WebKit](https://webkit.org/blog/18136/introducing-the-safari-mcp-server-for-web-developers/).

Use `python3 probe.py --gaps-only` to omit the Firefox, Chrome and Chrome CDP probes; Safari and Opera still require fresh sessions and Opera acquisition. The manual workflow defaults to `scope: gaps`; select `full` only when the broader suite is needed. New download and MCP cases are pending macOS execution; historical acceptance remains scoped to its recorded commit.

Apple documents [WebDriver isolation](https://developer.apple.com/documentation/safari-developer-tools/webdriver/) and the standard [Downloads directory](https://developer.apple.com/documentation/foundation/url/downloadsdirectory), but those documents do not guarantee the destination for this WebDriver session. [CDP Browser download methods and events](https://chromedevtools.github.io/devtools-protocol/tot/Browser/) are experimental. Safari MCP input schemas are read from the server rather than assumed.
